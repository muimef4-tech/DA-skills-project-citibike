🚲 Citi Bike: анализ поведения пользователей

📌 О проекте

Проект посвящён анализу поездок пользователей сервиса Citi Bike с целью выявить закономерности в использовании системы.

В рамках проекта исследуются:

- спрос в течение дня и недели;
- продолжительность и дистанция поездок;
- особенности маршрутов;
- поведение разных пользовательских сегментов;
- активность станций;
- различия между подписчиками и обычными клиентами;
- динамика поездок в течение наблюдаемого периода.

Основная аналитическая логика проекта:

Наблюдение → Вопрос → Гипотеза → Проверка → Результат → Инсайт → Рекомендация

---

🎯 Цель проекта

Понять, как пользователи используют Citi Bike, и определить основные различия в их поведении.

Основные вопросы:

1. В какое время спрос на Citi Bike максимален?
2. Как меняется продолжительность поездок?
3. Какие маршруты отличаются по длительности и дистанции?
4. Различается ли поведение разных пользовательских сегментов?
5. Отличаются ли наиболее загруженные станции от остальных?
6. Чем подписчики отличаются от обычных клиентов?
7. Как меняется активность пользователей в течение наблюдаемого периода?

---

🔎 Основные результаты

1. Спрос по времени

Количество поездок анализировалось по:

- дням недели;
- времени суток;
- отдельным временным периодам.

Большая часть поездок приходится на дневные и вечерние часы, тогда как ночная активность значительно ниже.

При этом различия между отдельными днями недели не являются настолько сильными, как различия между временными периодами внутри дня.

---

2. Продолжительность поездок

Продолжительность анализировалась одновременно через среднее и медианное значение.

Это важно, поскольку распределение длительности поездок может содержать длинный хвост из необычно продолжительных поездок.

Одно из основных наблюдений:

«Обычные клиенты в среднем совершают более длительные поездки, чем подписчики, несмотря на значительно меньшее количество поездок.»

---

3. Анализ маршрутов

Для маршрутов были рассчитаны:

- количество поездок;
- средняя продолжительность;
- медианная продолжительность;
- средняя дистанция;
- медианная дистанция.

Для сравнения использовались только маршруты с достаточным количеством наблюдений.

Это позволяет не путать популярность маршрута с его типичной продолжительностью.

Например, простое суммирование продолжительности может показать большой результат только потому, что по маршруту ездит много людей.

---

4. Поведение пользовательских сегментов

Были изучены различия между группами по:

- времени начала поездки;
- времени окончания поездки;
- типу подписки;
- возрасту;
- полу.

Для корректного сравнения использовались не только абсолютные значения, но и доли внутри каждой группы.

Это позволяет избежать ошибки, когда большая группа автоматически выглядит более активной только из-за своего размера.

---

5. Наиболее активные станции

Были определены Top-10 наиболее активных станций по количеству их появлений в качестве стартовой или конечной станции.

Top-10 сравнивались с остальными станциями по:

- количеству поездок;
- продолжительности;
- дистанции;
- структуре пользователей.

Таким образом, анализ отвечает не только на вопрос «какие станции самые популярные?», но и на вопрос:

««Отличается ли поведение пользователей на наиболее загруженных станциях?»»

---

6. Подписчики vs обычные клиенты

Пользовательские типы сравнивались по следующим показателям:

Показатель| Анализ
Количество поездок| ✓
Доля поездок| ✓
Средняя продолжительность| ✓
Медианная продолжительность| ✓
Средняя дистанция| ✓
Медианная дистанция| ✓
Среднее время начала| ✓
Время суток| ✓
Распределение дистанций| ✓

Основное наблюдение:

Подписчики формируют основную часть поездок, тогда как обычные клиенты в среднем совершают более длительные поездки.

---

7. Динамика поездок

Для каждого дня были рассчитаны:

- количество поездок;
- средняя продолжительность;
- медианная продолжительность;
- средняя дистанция.

Также была рассчитана корреляция между этими показателями.

Поскольку датасет охватывает ограниченный период, корректнее говорить о временной динамике, а не о полноценной сезонности.

🧠 Методология

Очистка данных

Проверялись:

- пропущенные значения;
- дубликаты;
- корректность дат;
- продолжительность поездок;
- соответствие времени начала и окончания;

- категориальные признаки.

---

Feature Engineering

Были созданы дополнительные признаки:

- дата;
- месяц;
- неделя;
- час;
- день недели;
- временной сегмент;
- продолжительность в минутах;
- сегмент продолжительности;
- географическая дистанция;
- сегмент дистанции;
- возраст;
- возрастная группа.

---

Расчёт дистанции

Для расчёта расстояния между станциями использовалась формула Haversine.

Она позволяет получить географическое расстояние между координатами двух станций.

Важно: это расстояние по прямой, а не фактический путь велосипеда по улицам.

⚠️ Ограничения анализа

1. Датасет охватывает ограниченный период, поэтому нельзя делать выводы о сезонности всего года.
2. Дистанция между станциями является географической, а не фактической дорожной дистанцией.
3. Корреляция не доказывает причинно-следственную связь.
4. Среднее значение чувствительно к выбросам, поэтому дополнительно используется медиана.
5. Для анализа маршрутов установлен минимальный порог количества поездок.
6. Наблюдаемые различия описывают поведение пользователей, но сами по себе не объясняют причины этого поведения.

📌 Главный вывод

Citi Bike используется разными группами пользователей по-разному.

Анализ показывает различия:

- в интенсивности использования;
- продолжительности поездок;
- временных паттернах;
- дистанции;
- активности станций;
- поведении подписчиков и обычных клиентов.

При этом проект построен не только вокруг описательной статистики. Основной акцент сделан на последовательной проверке гипотез:

Наблюдение → Вопрос → Гипотеза → Проверка → Результат → Инсайт

Это позволяет отделять подтверждённые закономерности от предположений и не превращать аналитику в древний ритуал «построил график → придумал причину».
